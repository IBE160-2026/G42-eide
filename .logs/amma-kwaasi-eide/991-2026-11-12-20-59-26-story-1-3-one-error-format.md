### Result
- **Implemented (commit `c2a3de4`, "feat: implement Story 1.3 one error format for every failure", 6 files, local only):**
  - `backend/app/contracts/errors.py` (new): the closed list of 18 codes with fixed HTTP statuses and the approved Norwegian messages; `ErrorResponse` `{error_code, message, limit?, reference_id?}`, validated against its code.
  - `backend/app/api/errors.py` (new): `AppError`; one shared builder that also writes the single log line; handlers for routing 404 (`not_found`), 405 (`method_not_allowed`, `Allow` kept), body-parsing 400 and validation errors (`invalid_request`), and any other framework error (`internal_error`); a pure ASGI catch-all inside CORS with an 8-hex `reference_id` that never re-raises or completes a started reply; empty `HEAD` replies; Uvicorn access log off; `app.errors` does not propagate.
  - `backend/app/application.py`: `redirect_slashes=False`, logging setup, handlers, catch-all inside `CORSMiddleware`.
  - `backend/tests/test_errors.py` (new): 76 tests; 164 backend tests in total.
  - Spec `done`; Story 1.3 `review` in `sprint-status.yaml` (only that line; Epic 1 stays `in-progress`).
- **Spec decisions (developer-approved):**
  - G-1 Option A/P1/H1; the 18 messages; the log line (`stage=api code=… duration_ms=…`, `reference_id` only for `internal_error`, INFO for 4xx, ERROR for 5xx).
  - Spec review: F1 no trailing-slash redirects (404 instead of a 307 that echoed the query); F2 after a reply has started, log once and return (verified with Uvicorn and curl: re-raising leaked the exception message, completing the reply made a truncated reply look successful); F3 every `internal_error` gets a `reference_id`, 5xx at ERROR, `not_found`/`method_not_allowed` framework-only, `limit` only for `file_too_large`; F4 empty `HEAD` replies; F5 extra tests; F6 logger `app.errors`.
  - Q1: any framework HTTP error without an approved mapping → `internal_error` (500), never overriding 400/404/405, preflights or `AppError` codes. Q2: replies Uvicorn sends before a request reaches the app are a known limitation.
  - **F6 amendment (review iteration 1):** `app.errors` does not propagate, so no line is duplicated when the root logger has handlers; recorded in the Spec Change Log.
