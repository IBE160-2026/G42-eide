- (decision) User chose Coaching path over Fast path — priority is understanding the process, not speed.
- (decision) Form factor: web app. Idea: AI Study Buddy for IBE160 course project — upload course material (PDF/text), AI generates summaries, flashcards, quiz Q&A, key concepts, and source/page references.
- (decision) Stakes: solo dev, beginner programmer, graded IBE160 course deliverable. Priorities: learning dev process, appropriate AI-assisted coding, documentation, testing/QA, ability to explain the build. Not commercial. Scope must be deliberately small/achievable.
- (event) Web research on comparables (Quizlet AI, NotebookLM, StudyFetch, Taskade) confirms core loop (upload->summary/flashcards/quiz) is table-stakes; citations/multi-format are differentiators, not needed for MVP. Known pipeline gotchas: table/figure handling, chunking, hallucination propagation, page-citation mapping.
- (decision) LLM approach: cloud LLM API (not local) — reasoning: simpler for a beginner to implement than self-hosting a model.
- (decision) Confidentiality goal: avoid storing uploaded documents unnecessarily. Exact persistence model (zero persistence vs session-only) still open — to be resolved.
- (decision) No deadline pressure but wants steady, understandable progress. Tech stack/language not yet decided — depends on course requirements/syllabus, which user will check separately. Test material: user's own course PDFs/notes.
- (decision) Confirmed: zero-persistence MVP (process uploaded file in memory, discard after generating outputs; no accounts, no saved history). Confirmed MVP feature split (must-have: single-file upload, course code/subject + detail level + output language inputs, one-pass generation of summary+flashcards+quiz+key concepts, page-number references, no login/no history). Postponed: multi-file/library, special table/figure handling, saving/editing/export, accounts/sharing, fine-grained citation.
- (decision) Accuracy/hallucination posture for MVP: prompt LLM to base output strictly on uploaded source material (lightweight mitigation), PLUS a visible disclosed limitation notice telling users AI-generated content should be verified against the original material. No complex verification logic built.
- (decision) Document size scope: MVP handles one reasonably-sized document at a time (e.g., one lecture's slides/notes). Oversized uploads are rejected with a message asking for a smaller document. No chunking or large-document handling in v1.
- (decision) Primary user for MVP: the developer themselves, testing with their own real course PDFs. Broader student audience is a future possibility, not an MVP design target. Personal success bar: upload a real lecture PDF -> get useful summary + flashcards + key concepts + quiz with page references, without crashing; plus personally understanding and being able to explain the main design/code decisions made.
- (decision) API cost/provider: not yet decided. Constraint: prefer free tier or lowest-cost practical option for development/testing; avoid committing to a paid provider before requirements are clearer. Flag as a constraint/risk in the brief, not a blocking decision.
