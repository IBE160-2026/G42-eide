## Intent

**User story** (`epics.md:968–988`): as a student, I want to see every quiz question and reveal each answer myself, so that I can check my understanding (display-only, no scoring).

**Problem:** after Story 1.19 the Quiz panel holds only its visually hidden `h3` (`ResultTabs.tsx:119`; the header comment `:33–34` says "Quiz holds only its h3; its content is Story 1.20"). The validated `results.quiz` (`{question, answer, pages}[]`, `contracts.ts:60–64`) reaches the browser and is counted in the tab label `Quiz (N)` (`ResultTabs.tsx:54`), but is not shown. It is the last empty result panel.

**Approach:** the Quiz panel shows every quiz item at once as an ordered list. Each item is a card holding the question as an `h4`, its own `Vis svar` / `Skjul svar` toggle, and the answer (hidden until revealed) with its page links from the existing `PageLinks`. A new `QuizList` component keeps the set of revealed items in component state; because the panel stays mounted while hidden, the revealed answers survive tab switches, and they reset when a new results session mounts `ResultTabs` again. The toggle reuses Story 1.19's `.button-secondary` unchanged. No backend, contract, fixture, `PageLinks`, `FlashcardDeck` or `.button-secondary` change.

**In scope:**
- the quiz list in the Quiz panel (questions, toggles, answers with page links);
- passing the existing `pdfSource` from `ResultTabs` to that panel;
- CSS for the list, the item card, the question and the answer, from existing tokens only (a new "Story 1.20" section appended to `globals.css`);
- Vitest coverage, and the narrow compatibility correction CC-20 to existing Story 1.16–1.19 tests (D9).

**Out of scope:**
- **[BINDING] banned features** (`epics.md:987`; UX-DR-40, `epics.md:280`; `EXPERIENCE.md:173, 244, 286`; PRD §6.2 and its Quiz glossary entry, `prd.md:46, 95, 158`): scoring, multiple-choice or any other selection, typed answers, saving quiz progress, and a "Vis alle svar" button. Interactive quiz-taking with scoring is Phase 2 (D-15, `epics.md:304`);
- `Tilbake til start`, the new-results-session trigger and demo acceptance (Story 1.21);
- real-mode results (Story 2.6), real-mode PDF sources (Story 2.7), `lang="en"` on English results (Story 2.6, AF-5; D8);
- any change to `backend/`, `samples/` (including `demo-response.json`), the API contract, dependencies or configuration; no paid API call;
- any change to `PageLinks`, `SummaryContent`, `KeyConceptsContent`, `FlashcardDeck`, `pdf-source.ts`, `DemoOutcome.tsx`, the Story 1.4–1.19 CSS rules (including `.page`, `.button-secondary` and the D3a media block), any token, or the global `.sr-only` and `:focus-visible` rules;
- any media query, responsive variant or page-padding change in this story (if D5 as recommended; a cross-story page-padding amendment, if the developer opens one under D5, is a separate approved change outside this story);
- any change to a frozen spec block, to `DESIGN.md` or `EXPERIENCE.md`, and any change to the status of Story 1.16's open manual checks.

## Decisions

All nine decisions below were [OPEN] until G0 and were **approved by the developer at G0 (Checkpoint 259, 2026-11-22), each as recommended**; they are binding. The proposed design (PD1–PD6) and the matrix were written for the recommended options, so every passage marked "(if D*n* as recommended)" applies. D5 and D7 carry the approval boundaries stated in their "G0 approval" bullets.

- **D1 — page-link visibility [APPROVED]:**
  - *Sources:* Story 1.20 AC 1 ("the hidden answer and its page links", `epics.md:980`); UX-DR-26 (`… → answer → page links`, `epics.md:257`); `EXPERIENCE.md:173` (question → button → answer → page links); `DESIGN.md:390` ("revealed answer … → page link(s)"); Story 1.19 D8 (links inside the hidden flashcard answer, `spec-1-19…:139–142`). Conflict: the approved mockup shows each item's page link next to the button, visible while the answer is collapsed (`mockups/direction-refined-rolig.html:304, 308`); the spines win over the mockup (`EXPERIENCE.md:21`).
  - *Options:* (a) the links are inside each item's hidden answer element, after the answer text, and are shown and hidden with it; (b) the links are always visible, after the answer element and outside it.
  - *Recommendation:* **(a)**. It follows the approved DOM order and the AC's wording, matches Story 1.19, and keeps hidden links out of the focus order until the answer is revealed.
  - *Consequences:* (a) QZ6, QP2, QP4 and CC-20 item 4 are written for it: all six fixture links are in the DOM from the start (inside `[hidden]` answers), so the link count in PS3 grows by six, but none is focusable or exposed to role queries until its answer is revealed. (b) would add up to six focus stops while all answers are collapsed, show a citation before its answer, and change PD1, QZ6, QP4 and the PS3 replacement.

- **D2 — question numbering [APPROVED]:**
  - *Sources:* `DESIGN.md:390` ("numbered question as heading"); `EXPERIENCE.md:173` (`<ol>`, "the list keeps its semantics"); UX-DR-26 (`<ol>`); UX-DR-36 (accessible name = visible label). Conflict: the mockup removes the list markers (`list-style: none`) and types "1." into the heading text (`mockups/direction-refined-rolig.html:184, 302`).
  - *Options:* (a) native `<ol>` numbering: the browser's list marker (`1.`, `2.`, …) shows the number beside each card, and the `h4` holds only the question text; (b) `list-style: none` and the number written into the `h4` text (`1. Hva …`), as in the mockup; (c) `list-style: none` and a CSS-generated number (`::before` with a counter).
  - *Recommendation:* **(a)**. The questions are visibly numbered by the ordered list itself; the number exists once (as the list marker), the `h4`'s accessible name stays exactly the question, and no text or generated content is added. (b) adds the number to the heading's accessible name and text not in the data, and `list-style: none` can remove list semantics in Safari/VoiceOver unless a `role="list"` is added (contrary to "keeps its semantics" and to this spec's no-`role` rule). (c) has the same list-semantics risk, and generated content is included in the heading's accessible name in Chromium.
  - *Trade-offs of (a), stated plainly (R251-10):*
    - **How the number reaches assistive technology:** browsers expose the marker as list-marker text in the accessibility tree; screen readers typically read it when reading the list item in order, and announce the list ("list, 5 items") on entering it. Whether and how the marker is spoken depends on the screen reader and browser; 1.20-M4 records it rather than this spec assuming it.
    - **Heading navigation:** a user who moves by heading (Narrator scan-mode `H`, or a headings list) hears the question without its number, because the number is not part of the `h4`. "Numbered question as heading" (`DESIGN.md:390`) is therefore met **visually** (the number sits beside the heading) and through list semantics, not inside the heading's name. Options (b)/(c) would put the number into the heading name at the cost described above.
    - **Marker appearance:** the marker uses the browser default `::marker` style, in the inherited body font (17px, weight 400, text colour), outside the card's left border; it is not styled as part of the heading.
    - **Indent:** the marker needs a left indent on the list (PD5: `var(--space-6)`, 24px; enough for `1.`–`9.`). This shifts the quiz cards 24px right of the content edge used by the other panels (the summary paragraph, the key-concept list and the flashcard card start at the panel's content edge), and it costs 24px of text width at every width (D5). A two-digit marker such as `10.` (real-mode lists of ten or more) may extend into the panel padding: visible, not clipped.
    - **Link to D5 (R253-07): decide D2 and D5 together.** The 24px indent is a quiz-only cost created by D2 (a). Without it (D2 (b) or (c), markers removed) the answer would get about 127px at 320 CSS px instead of about 103px, more than any single quiz-only lever in D5, but at the list-semantics and accessible-name costs stated above. A smaller indent (D5 lever L2, 16px, about 111px) keeps native markers but leaves less room: at 320 CSS px a `10.` marker overhangs into the 16px panel padding. This spec does not recommend changing the list design for width; it records the trade-off so the developer can weigh it with D5.
  - *Consequences:* (a) PD1, PD5, QZ1, QZ2 and QR1 are written for it; 1.20-M1/M2 check that the numbers are visible and not clipped; 1.20-M4 records whether the number is read. DESIGN's phrase is interpreted in CF-1. (b) or (c) would change PD1, PD5, QZ2, QR1 and the Strings table (b).

- **D3 — typography and spacing [APPROVED]:**

## Proposed design [FOR-G0]

Written for the recommended options of D1–D9.

- **PD1 — component and markup:** a new `frontend/components/QuizList.tsx` (props `{ items: readonly ValidatedQuizItem[]; pdfSource: string | null }`) renders, in response order:
  ```tsx
  <ol className="quiz-list">
    {items.map((item, index) => {
      const revealed = revealedItems.has(index);
      const answerId = `${baseId}-answer-${index}`;
      return (
        <li key={index} className="quiz-item">
          <h4 className="quiz-item__question">{item.question}</h4>
          <button type="button" className="button-secondary quiz-item__toggle"
                  aria-expanded={revealed} aria-controls={answerId} onClick={() => toggle(index)}>
            {revealed ? "Skjul svar" : "Vis svar"}
          </button>
          <div id={answerId} className="quiz-item__answer" hidden={!revealed}>
            <p className="quiz-item__answer-text">{item.answer}</p>
            <PageLinks pages={item.pages} pdfSource={pdfSource} />
          </div>
        </li>
      );
    })}
  </ol>
  ```
  - keys are the index: questions are not guaranteed unique and the list is never reordered (Story 1.18 precedent);
  - the `h4` holds only the question text and has no `id` (D2, D7); no `lang`, `role`, `aria-label`, `aria-describedby` or `aria-labelledby` anywhere in the list (D7, D8);
  - the toggle's class is exactly `button-secondary quiz-item__toggle`; it is never `aria-disabled` and never natively disabled; the component uses no identifier named `disabled`; `.quiz-item__toggle` is a hook class with no CSS rule;
  - the buttons are never re-keyed or re-mounted when an answer is toggled, so focus stays on the pressed toggle;
  - `ResultTabs` renders `<QuizList items={results.quiz} pdfSource={pdfSource} />` in the panel whose `tab.key === "quiz"`, after the `h3`, and updates its header comment (`:26–34`); the other panels, the tab list, its keyboard handling and its focus behaviour are unchanged.
- **PD2 — state, persistence and reset:** one `useState<ReadonlySet<number>>` of revealed item indices, initially empty; `toggle(index)` copies the set and adds or removes only that index. Revealed answers survive tab switches because the Quiz panel stays mounted while `hidden` (Story 1.16 D12). They reset because a new results session remounts `ResultTabs` (`DemoOutcome` renders it only in the success phase, and every new pass goes through the loading phase first; Story 1.19 D2, `spec-1-19…:114`); Story 1.21 owns the `Tilbake til start` trigger. The list does not reset itself on a changed `items` prop. Unlike the flashcard index, a stale index cannot throw, but without a remount revealed state could attach to different questions; the existing Story 1.21 follow-up in `issues.md` therefore covers the quiz as well (to be noted at the documentation step). Nothing is written to storage, cookies or the network.
- **PD3 — answer ids:** one `useId()` per list; each answer's id is `${baseId}-answer-${index}`, so ids are unique within a list and across two lists. Tests read each id from the toggle's `aria-controls` and resolve it with `document.getElementById`, assuming no id format.
- **PD4 — no announcements:** no `aria-live` element and no write to the global status region; `aria-expanded` conveys the state change on the focused toggle.
- **PD5 — CSS (if D2, D3, D5 and D6 as recommended):** appended after the D3a media block, existing tokens only, flat rules in this order, preceded by a comment line `/* --- Story 1.20: the Quiz panel (…; UX-DR-26) --- */`:
  - `.quiz-list`: `margin: 0; padding: 0 0 0 var(--space-6);` (native markers kept, D2);
  - `.quiz-item`: `padding: var(--padding-quiz-item); background: var(--color-surface); border: var(--border-hairline) solid var(--color-border-subtle); border-radius: var(--radius-lg);`
  - `.quiz-item + .quiz-item`: `margin-top: var(--space-3);`
  - `.quiz-item__question`: `margin: 0 0 var(--space-3); white-space: pre-line; overflow-wrap: anywhere; color: var(--color-text);` plus the three `--font-subheading-*` tokens. `overflow-wrap: anywhere` follows `DESIGN.md:346`; `white-space: pre-line` is a **[FOR-G0]** choice, not required by a quiz source, made for consistency with the flashcard term, the summary and the key concepts (it keeps any line break in a generated question) (R251-16);
  - `.quiz-item__answer`: `margin: var(--space-3) 0 0;` (no `display`);
  - `.quiz-item__answer-text`: `max-width: var(--measure-answer); margin: 0; padding-left: var(--space-3); border-left: var(--border-emphasis) solid var(--color-primary); white-space: pre-line; overflow-wrap: anywhere; color: var(--color-text);` plus the three `--font-body-*` tokens (D3 (b)). Because the font is declared on this element, `65ch` is measured in the 17px body font; because `box-sizing` is `border-box` (`globals.css:122`), the 65ch `max-width` includes the 3px rule and the 12px left padding, so the text itself is at most 65ch − 15px wide (R253-10).
  The rule is on the answer text, so the page-link row below it (Story 1.17 `.page-links`, `margin: var(--space-3) 0 0`, small type) sits under the ruled answer without the rule, matching `DESIGN.md:390` ("revealed answer … with a 3px rule … → page link(s)"). The toggle gets its look from `.button-secondary` only. No media query, `vw` value, `hyphens` declaration or `::marker` rule; no `.result-panel` selector, no `:focus-visible` or `outline` (the global focus ring applies to the toggle and the links).
