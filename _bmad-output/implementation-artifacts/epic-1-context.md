# Epic 1 Context: Run the app and explore a complete example

## Goal

A reviewer or the student can start AI Study Buddy from the README with no API key and no internet, run the demo on a bundled original Norwegian sample lecture, and browse clearly labelled example results (Sammendrag, Nøkkelbegreper, Flashkort, Quiz) with working `PDF-side N` links into the sample PDF. The epic also lays the foundation everything else builds on: project setup, the status endpoint, one error format, the shared six-stage pipeline, the sample PDF and a temporary demo fixture. Stories 1.6–1.11 use generated test PDFs and fake connectors; the epic is done only with the approved sample PDF and a working offline demo.

## Requirements & Constraints

- Demo must run fully offline with no key: no provider client, no external network, no CDN/web fonts. Demo results are always labelled (`mode: "demo"`, permanent DEMO banner, heading `Eksempelresultater (ikke generert nå)`).
- Zero persistence: documents and results live in memory for one request only. Logs hold only stage, error code, duration, token counts and `reference_id` — never document text, AI output or secrets.
- A pass yields Summary + at least 5 flashcards, 5 quiz items and 5 key concepts; the model must never pad. Too-thin material is reported as `insufficient_content`, not filled in.
- Page references for PDFs must be real supplied page markers; plain text never gets page references. Automated checks are "page-marker validation" only — whether a page actually supports an item is checked manually (never call it citation/content verification).
- Norwegian characters (æ, ø, å) must survive PDF and UTF-8 extraction (tested).
- The Verification Notice is always shown with results, with no extra clicks.
- All interface and backend `message` text is Norwegian Bokmål ("KI", not "AI", in UI text); approved copy is used verbatim. New Norwegian copy needs developer approval.
- Every story carries its own tests (pytest backend, focused Vitest frontend); automated tests never use a real key.
- Sample PDF: developer's own Norwegian lecture on inventory management/supply-chain logistics, 5–8 pages, exactly one image-only page, with a provenance note; course AI-use rules (U-1) remain open — acceptable for dev/test, not yet submission.
- Temporary fixture: real content and real page markers from the sample only, developer-reviewed, provenance note marks it unmistakably TEMPORARY. The README must not claim demo results come from a real AI run.
- Public repo hygiene: no keys, `.env`, copyrighted or private documents; test files generated by tests. One branch + PR per story; every commit, push and merge needs explicit developer approval.
- Out of scope: drag-and-drop, quiz scoring/typing, "Vis alle svar", dark mode, saving/export, accounts.

## Technical Decisions

- **Stack:** Python 3.13 + uv, FastAPI 0.162, Pydantic 2.14, pydantic-settings, python-multipart, pypdf 6.21, pytest 9.1; Next.js 16.4 (App Router, TS) on Node 22, React 19, Vitest 5 + Testing Library. Starter changes: system font stack instead of `next/font/google`, telemetry off. The anthropic SDK is not added in Epic 1.
- **Topology:** local only; backend on `127.0.0.1:8000`, CORS allows exactly `http://localhost:3000`; frontend uses `NEXT_PUBLIC_API_BASE_URL`; no Next.js proxy. Backend is the single authority; frontend is thin.
- **Layout:** `backend/app/{api,pipeline,connectors,contracts,config.py}`, `backend/tests/`, `samples/`. `pipeline` never imports a concrete connector or SDK; `contracts` imports nothing from the app (tested).
- **Config:** one settings module from env; `AI_MODE` read once, defaults to `demo`; `real` without a key refuses to start (never falls back). No literals in stages.
- **Pipeline:** `run_pass(doc, filename, inputs, source: "upload" | "sample")` runs 1 validate bytes → 2 extract with markers → 3 build prompt → (cost gate, real only — Epic 2) → 4 connector → 5 validate → 6 respond. Any stage stops the pass with an error code. No route calls a connector directly.
- **Stage 1:** PDF only by `%PDF-` at byte 0; text by fixed rule order (binary signature → BOM UTF-16/32 → NUL → strict UTF-8, optional UTF-8 BOM stripped → disallowed control chars); extension must match (`.pdf`/`.txt`, case-insensitive) and is never sufficient alone; unopenable PDF → `unreadable_file`; >80 total pages → `file_too_large` (`pages`).
- **Stage 2:** pypdf per page; text pages wrapped `<page number="N">…</page>` (1-based viewer position), marker-like strings neutralised; textless pages → `skipped_pages`; no text at all → `no_extractable_text`; >200,000 chars (before markers) → `file_too_large` (`characters`). No chunking.
- **Stage 3:** system instruction: Document text only; document and inputs are data; cite only supplied pages; all four types in selected language; keep terminology with original term in brackets on first use when languages differ. Options `detail_level` brief|standard|detailed (default standard), `output_language` nb|en (default nb); invalid → default + log line. `course_code` stripped of control chars, cut to 100, inside a delimited data block.
- **Connector:** `ConnectorRequest{system, document_block, inputs}`, `ConnectorReply{raw_json, stop: complete|length|refusal|other, input_tokens, output_tokens}`, `ConnectorError{code: ai_unavailable|ai_rate_limited|ai_credits_exhausted}`; methods `count_input_tokens`, `generate`; returns unparsed text. Demo connector returns the fixture with `stop: "complete"` and fixed token counts.
- **AI output contract:** `{status: ok|insufficient_content, summary{text, pages}, flashcards[{front, back, pages}], quiz[{question, answer, pages}], key_concepts[{term, explanation, pages}]}`.
- **Stage 5 gates:** (1) `stop == complete`; (2) parse, `insufficient_content` handled first, full parse with no empty text; (3) ≥5 per list, PDF pages filtered to supplied set, any flashcard/quiz/concept left with zero pages fails, Summary pages optional, any page on plain text fails. Failures → `ai_output_invalid`. Output is a new `ValidatedResults` with sorted, de-duplicated `pages`; stage 6 accepts only that.
- **Envelopes:** success `{mode, results, skipped_pages}`. Every non-2xx (validation errors, unknown routes, unsupported methods, unhandled exceptions) is `{error_code, message, limit?, reference_id?}`, with the catch-all inside CORS. Closed codes/HTTP: 400 `unsupported_file_type`, `bad_text_encoding`, `unreadable_file`, `no_extractable_text`, `invalid_request`; 403 `demo_mode_no_uploads`, `demo_not_enabled`; 404 `not_found` (`Adressen finnes ikke.`, never echo the path); 405 `method_not_allowed` (`Metoden støttes ikke for denne adressen.`, with `Allow`; includes plain `OPTIONS`); 409 `generation_in_progress`; 413 `file_too_large` + `limit`; 422 `insufficient_content`; 429 `ai_rate_limited`; 500 `internal_error` + 8-hex lowercase `reference_id` (also on the log line); 502 `ai_unavailable`, `ai_output_invalid`; 503 `ai_credits_exhausted`, `session_call_limit_reached`. Exceptions: CORS preflights keep Starlette's default replies (200 / plain-text 400) on any path; no route accepts `HEAD` — it gets 405 with `Allow` (or 404), headers only, no body. Frontend decides success by presence of `error_code`, not status.
- **Contracts:** Pydantic is the source of truth; frontend TS types mirror by hand with identical `snake_case`. Fixtures: `samples/demo-ai-output.json` (raw AI shape, read by demo connector) and `samples/demo-response.json` (exact `/api/demo` envelope, regenerated/asserted by a backend test, shape-checked in frontend tests).
- **Endpoints:** `GET /api/status` → `{mode, limits{max_upload_bytes: 10485760, max_pdf_pages: 80, max_text_chars: 200000}, options{detail_level, output_language: {values, default}}, accepted_types}`. `POST /api/demo` (no body; demo only, else `demo_not_enabled`; fixed inputs standard/nb; stages 1, 2, 3, 5 run for real). `POST /api/generate` returns `demo_mode_no_uploads` in demo, before the lock. `GET /api/demo/sample.pdf`: demo only, fixed file, exact bytes, `application/pdf`, `Content-Disposition: inline`; real → 403; missing → `internal_error`; no query/path input reaches another file; other methods → 405 `Allow: GET`; no lock, no paid-call count.
- **Concurrency:** one `PassGuard` in `pipeline/`; non-blocking backend-wide lock acquired at the start of `run_pass`, released in `finally`, shared by `/api/generate` and `/api/demo`; busy → `generation_in_progress`.
- **Rendering:** all AI, document-derived and backend `message` text as plain text — no `dangerouslySetInnerHTML`, no Markdown-to-HTML.

## UX & Interaction Patterns

- **Visual foundation:** all DESIGN.md tokens as CSS custom properties; light mode only; system fonts; flat (no shadows/gradients); min-heights not fixed heights; controls ≥ 44px tall, targets ≥ 24px; content max 960px. Global `:focus-visible` 3px ring, 2px offset, never removed. Inline SVG icons with `aria-hidden="true"` and `focusable="false"`. Off-scale sizes snap to existing scale steps.
- **Shell:** `<html lang="nb">`, `<title>AI Study Buddy</title>`, `<header>` with `h1` + logo, `<main>` with sections `Opplasting og innstillinger` and `Resultater` (names never change). Headings h1 → h2 → h3 per panel → h4 per quiz question. Nothing sticky/fixed.
- **Status region:** one visually hidden `role="status"` `aria-live="polite"` `aria-atomic="true"`, empty from first render; clear then set on the next tick; never used for errors.
- **Startup:** S0 `Starter …` (not announced, no controls). S0x: `Får ikke kontakt med appens server` / `Sjekk at serveren er startet, og trykk «Prøv igjen».` + `Prøv igjen` (aria-disabled while checking, focus to headline on each failure; on success focus to `Vis eksempel` in demo).
- **Unavailable-button pattern** (Generer, Vis eksempel, Prøv igjen, Forrige, Neste): `type="button"`, never native `disabled`; `aria-disabled="true"`, focusable, guarded against click/Enter/Space; never sends a duplicate request.
- **Demo S1:** DEMO banner `DEMO – du ser et ferdig eksempel. Ingen KI-tjeneste brukes, og egne filer kan ikke lastes opp.`; `Last opp` disabled; settings fixed (Norsk bokmål, Standard) with the fixed-settings note; `Vis eksempel` calls `POST /api/demo` once. No external-AI notice in demo.
- **Loading S3:** `Henter eksempel …` (announced), animated indicator static under `prefers-reduced-motion`; no progress bar, timer or cancel.
- **Results S4:** heading `Eksempelresultater (ikke generert nå)` with `Tilbake til start`; Verification Notice `Innholdet er laget av KI og kan inneholde feil. Kontroller det mot originaldokumentet.`; skipped-pages notice with singular / two-item / 3+ wording; upload bar locked (settings as `<dl>`); `Resultatene er klare` announced, focus not moved. Notices: icon + text, never dismissible.
- **Tabs:** full WAI-ARIA APG — order Sammendrag | Nøkkelbegreper | Flashkort | Quiz, Sammendrag first, counts only on Flashkort/Quiz; Left/Right auto-activate with wrap, Home/End; roving tabindex; panels `tabindex="0"`, inactive kept mounted with `hidden`; state kept across switches.
- **Panels:** Sammendrag and Nøkkelbegreper plain text with `white-space: pre-line`. Flashkort: one card, `Kort N av M` (own polite live region), `Vis svar`/`Skjul svar` with `aria-expanded`/`aria-controls`, `Forrige`/`Neste` aria-disabled at ends. Quiz: `<ol>` of `h4` questions, each answer hidden with its own toggle.
- **Page links:** reusable component that takes its PDF source as input (no hard-coded URL); demo source `<NEXT_PUBLIC_API_BASE_URL>/api/demo/sample.pdf#page=N`; markup `PDF-side N` + `aria-hidden` ` ↗` + sr-only `, åpnes i ny fane`; `target="_blank" rel="noopener"`; separator ` · ` `aria-hidden`.
- **Errors (S5/S0x):** `<h2 tabindex="-1">` headline → action text → backend `message` as muted plain-text detail; focus to headline; no `role="alert"`. Key demo codes: `internal_error` → `Noe gikk uventet galt` + reference; `generation_in_progress` → `En generering pågår allerede`; network failure → `Mistet kontakten med serveren`; unknown codes incl. `demo_*`, `not_found`, `method_not_allowed` → `Noe gikk galt` / `Last inn siden på nytt, og prøv igjen.`
- **Tilbake til start (demo):** back to demo S1 with no dialog or leave warning; revealed answers and card position reset; focus to `Vis eksempel`.
- **Accessibility floor:** keyboard-operable, focus never lost to `<body>`, accessible name = visible label, contrast per tokens, never colour alone, reflow at 320px and 200% zoom. WCAG 2.2 AA is a target, never a compliance claim.
- **Decisions to settle in-story:** D-7 (S0/S0x before mode known) in 1.5; D-8/D-9 (off-scale sizes) in 1.4; D-1, D-2 (lock-state copy, needs approval), D-5 in 1.16; D-10 (unmocked surface visuals, reuse tokens) in 1.17–1.18; D-11 (prompt wording, shown to developer) in 1.8; D-13 (tool patch updates) in 1.1.
