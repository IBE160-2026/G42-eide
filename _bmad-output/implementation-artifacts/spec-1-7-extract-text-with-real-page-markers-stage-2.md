## Intent

**Problem:** Stage 1 only confirms that a document is a supported PDF or text file; nothing yet extracts its text with real page numbers, so later stages have no text to send and no trustworthy set of pages to check page references against.

**Approach:** Add stage 2 in `backend/app/pipeline/`: take stage 1's `CheckedPdf` or `CheckedText`, extract PDF text per page with pypdf, wrap every page with text in a real page marker, neutralise marker-like strings, record supplied and skipped pages, and stop with `no_extractable_text` or `file_too_large` (`characters`) in the approved order. Covered by pytest with generated files.

## Boundaries & Constraints

**Always:**
- Input is exactly stage 1's result (`CheckedPdf(reader, page_count)` or `CheckedText(text)`); the PDF is not reopened. The character limit comes from the caller (settings), never a literal (AR-15).
- Page numbers are the 1-based PDF viewer position (`reader.pages` index + 1), never a printed page label (AD-8).
- Order: extract → `no_extractable_text` → character limit → build the result. No AI call, no chunking (AR-9, AR-15).
- Failures raise `PassFailure` with codes from the closed list only. What stage 2 itself controls carries no document text, filename or raw pypdf exception detail: the error, its traceback context (`raise … from None`, as in stage 1), and log output (stage 2 writes none).
- pypdf's own internal warnings and logging are outside that guarantee: its logging configuration is left unchanged and its warnings are not suppressed (Story 1.6 decision 7 carried over); they remain subject to the deferred Story 1.6 item.
- Every test file is generated by the tests; nothing is downloaded or committed as a fixture (AR-20).

**Never:**
- Import `app.api` from `app.pipeline`, or change stage 1, `PassFailure`, `AppError`, contracts or settings.
- Add a route, `run_pass`, the prompt (Story 1.8), output validation (Story 1.10), `PassGuard`, frontend or README changes.
- Add dependencies (including reportlab or `cryptography`) or change lockfiles or CI.

## Decisions (developer, 2026-11-13, all option A)

1. **Result type:** one frozen `ExtractedDocument(kind, text, supplied_pages, skipped_pages)`; `kind` is `"pdf"` or `"text"`; both page collections are immutable, sorted tuples of `int`.
2. **Pages without text:** a PDF page whose extracted text is empty after stripping (whitespace-only included) is skipped: no marker, its number goes into `skipped_pages`. Real 1-based viewer positions are kept, so numbering never shifts.
3. **Character limit:** `max_text_chars` is applied with Python `len()` to the **original** extracted text, before trimming, neutralising, page markers or separators. PDFs: the sum of every page's original extracted text length, including whitespace-only pages. Text files: the original decoded text from stage 1. Exactly `max_text_chars` passes; one character more → `file_too_large`, `limit: "characters"`.
4. **Neutralising:** a marker-like page tag is `<`, optional whitespace, an optional `/`, optional whitespace, then `page` in any case, followed by whitespace, `/`, `>` or the end of the text. Its leading `<` is replaced with `&lt;`; the rest of the match and all other text stay unchanged. Lookalikes such as `<pagination>`, `<pagebreak>`, `<pages>` or `<page-1>` are not changed.
5. **Plain text:** the same neutralising is applied to text documents, but no real markers are added; `supplied_pages` and `skipped_pages` are both `()`. The text is otherwise unchanged (not trimmed).
6. **Extraction errors:** any exception while reading or extracting any PDF page → `PassFailure("unreadable_file")` for the whole document, never a skipped page.
7. **PDF layout:** each page with text becomes `<page number="N">` + `\n` + the page text trimmed at both ends and neutralised + `\n` + `</page>`; marked pages are joined with a single `\n`, in page order.
8. **Unicode:** Norwegian characters (æ, ø, å, Æ, Ø, Å) and other text are preserved exactly; no normalisation.
9. **Order:** `no_extractable_text` is checked first (no page with text, or a text document empty after stripping), then the character limit, then the result is built. No AI call in this story.
- **Architecture source:** `ARCHITECTURE-SPINE.md` only (AD-1, AD-8, AD-14).

## Implementation Notes

- `stage2_extract.py` extracts every PDF page first inside one `try` (`_extract_pages`); any exception → `PassFailure("unreadable_file") from None`. Only after every page was read do the checks run: `no_extractable_text`, then the character limit, then the result (decisions 6 and 9).
- Neutralising is the private `_neutralise()` around the single compiled pattern from Design Notes (renamed from the public `neutralise()` after review, O1); plain text is neutralised but not trimmed.
- The `extract_document` docstring states the contract later stages rely on: the three codes, their order, and that `max_text_chars` counts the original extracted text (O3).
- Tests (63) generate PDFs with pypdf only: text pages via a Type1 Helvetica / WinAnsi content stream, image-only pages via an image XObject, whitespace-only and empty pages. The helper uses pypdf's private `PdfWriter._add_object` (no public alternative in 6.21); a pypdf upgrade could break the test helper, not production code.
- The decision 4 lookalike regression tests (T3) run through `CheckedText`, because the cp1252 test font cannot draw U+200B or U+FF1C; the same `_neutralise()` handles PDF pages.
- Review findings D1 (retained `__context__`) and L1 (invisible-only text) are recorded in `deferred-work.md`; `sprint-status.yaml` was not changed during implementation, at the developer's instruction.

## Design Notes

- Pattern for decision 4 (Python, case-insensitive): `re.compile(r"<(?=\s*/?\s*page(?:[\s/>]|$))", re.IGNORECASE)`, replaced with `"&lt;"`. The lookahead keeps the matched text after `<` unchanged; `[\s/>]|$` is what separates `<page …>` from `<pagination>` or `<page-1>`. A second pass finds nothing more, so the result is stable.
- Trimming (decision 7) uses `str.strip()`; the emptiness test (decision 2) uses the same `strip()`, so a page is marked exactly when its trimmed text is non-empty.
- Extraction of all pages happens first, inside one `try` that maps any exception to `unreadable_file` (decision 6); the order checks (decision 9) run only after every page was read.
- Plain text is neutralised but not trimmed (decision 5), so stage 3 receives the document text as written, minus fake tags.
- **Spec length:** kept as one specification (≈ 3,000 tokens), above the workflow's 1,600-token guideline; approved by the developer at Checkpoint 1 (2026-11-13).
